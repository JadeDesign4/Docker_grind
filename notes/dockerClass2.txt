### Step 1: Build the Image
You need to tell Docker to read that file and build an "image" out of it. We use the `-t` flag to give it a "tag" (a name) so we can find it easily. 

Make sure you are inside the `practice-dir` and run:

```bash

```
> **Note:** Don't forget that little dot `.` at the end! It tells Docker to look in the *current* directory for the Dockerfile.

	I ASKED A QUESTION:-
		"I understand It clearer than yesterday now, we hv to create a new folder and place a new Dockerfile in it, tag, build and run it from that folder. Hence, from what I understand multiple Dockerfile can't be in the same folder"

	THE RESPONSE I GOT:-
		Exactly! You hit the nail on the head. 

In Docker, the folder you are in is called the **Build Context**. When you run `docker build .`, Docker looks for a file specifically named `Dockerfile` in that exact spot. 

### Why you usually keep them separate:
* **One Project, One Goal:** If you put two `Dockerfile`s in one folder, how would Docker know which one you want to build? It defaults to the one named `Dockerfile`.
* **Cleanliness:** By using separate folders like `day1` and `practice-dir`, you ensure that the files for one container don't accidentally get sucked into another one.

### The "Pro" Exception (Just so you know):
You actually *can* have multiple in one folder if you rename them (e.g., `Dockerfile.web` and `Dockerfile.db`), but you have to use a special flag:
`docker build -f Dockerfile.web -t my-image .`

**But don't do that yet.** Stick to your current method of one folder per project. It’s the standard way to stay organized, especially when you start adding other files like scripts or configuration files to your containers.
